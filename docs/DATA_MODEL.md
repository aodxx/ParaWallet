# ParaWallet Google Sheets Data Model

Each tab has one stable header row that is created by `Repositories.bootstrap()`. The header order is part of the API/data contract because `Repositories.append()` writes values by these exact keys and `Repositories.rows_()` reconstructs objects from the same header row. IDs are UUID strings generated by Apps Script. Timestamps are ISO-8601 strings, and financial values are rounded to two decimals by the server calculator.

## Bootstrap behavior

`Repositories.bootstrap()` opens the spreadsheet from `SHEET_ID`, creates any missing tab, writes the complete header row with `setValues()`, and freezes row 1 for newly initialized tabs. If a tab already contains data, the function does not overwrite it. Instead, it validates the existing header row and throws `SCHEMA_MISMATCH:<tab>` when the order or names differ. This fail-fast behavior prevents silent column corruption.

The function returns `sheets`, `created`, `initialized`, and `validated` arrays so an administrator can see exactly what happened. Use `Repositories.validateSchema()` for a non-destructive report of every tab, including missing, empty, valid, or mismatched status.

A sale stores the agreement ID and the exact percentages used at creation time. Later agreement versions therefore cannot mutate historical sale calculations. Wallet balances are derived from confirmed sales and confirmed payments, with WalletTransactions providing an auditable movement trail.
